# 16. Database Design

## 16.1 Purpose

The **Database Layer** is the **Persistent Knowledge and State Management System** of the AI Cloud Operating System (AIOS).

Its responsibility is to securely store operational data, infrastructure metadata, workload information, scheduling decisions, telemetry summaries, learning datasets, business information, historical events, and system configuration.

Unlike Prometheus, which stores **high-frequency time-series metrics**, the database stores **structured, relational, transactional, and historical information** that enables processors.py to make intelligent, explainable, and continuously improving decisions.

The Database Layer acts as the **long-term memory** of AIOS.

---

# 16.2 Objectives

The Database Layer shall:

* Persist operational state.
* Store workload history.
* Store infrastructure metadata.
* Record AI decisions.
* Maintain learning datasets.
* Preserve historical events.
* Support predictive analytics.
* Maintain audit logs.
* Store business configuration.
* Enable disaster recovery.

# 16.10 Redis Integration

Redis provides high-speed in-memory data.

Uses

* Active Sessions
* Workload Queue
* Event Queue
* Distributed Locks
* Cache
* Temporary State
* Real-Time Notifications

Redis is never the primary persistent store.

# 16.11 Database Access Layer

All database access is performed through a dedicated Data Access Layer (DAL).

```text id="b3b7gg"

↓

ORM

↓

↓
```

* Loose coupling
* Easier testing
* Better security
* Transaction management
* Future database replacement

| Audit Logs            | Permanent        |
| Configuration History | Permanent        |
| Events                | 2 Years          |
| Learning Data         | Permanent        |
| Predictions           | 1 Year           |
| Cached Data (Redis)   | Minutes to Hours |

# 16.13 Backup & Recovery

The database shall support:

* Daily full backups
* Incremental backups
* Point-in-Time Recovery (PITR)
* Replication
* Automatic failover
* Disaster recovery testing

Recovery objectives

* RPO (Recovery Point Objective): < 5 minutes
* RTO (Recovery Time Objective): < 15 minutes

---

# 16.14 Security

Security controls include:

* Role-Based Access Control (RBAC)
* Encrypted connections (TLS)
* Encryption at rest
* Secret management
* Row-Level Security (where appropriate)
* Audit logging
* Credential rotation
* Least-privilege access

Only authorized AIOS services may read or modify operational data.

# 16.16 Functional Requirements

The Database Layer shall:

* Use PostgreSQL as the primary relational database.
* Use Redis for caching, queues, and transient state.
* Persist companies, users, workloads, infrastructure metadata, scheduling decisions, events, predictions, learning datasets, configurations, and audit logs.
* Separate transactional data from time-series metrics, with Prometheus remaining the authoritative metrics store.
* Support ACID-compliant transactions for critical operational data.
* Provide a secure Data Access Layer for all application components.
* Maintain historical data for learning, analytics, and explainability.
* Support backup, replication, and disaster recovery.
* Enable processors.py to access historical knowledge while remaining independent of database implementation details through the Repository/Data Access Layer abstraction.
