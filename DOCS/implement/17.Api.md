# 17. API Specification

## 17.1 Purpose

The **API Layer** is the **communication backbone** of the AI Cloud Operating System (AIOS).

It provides secure, scalable, and versioned interfaces between the **Next.js frontend**, **Django backend**, **processors.py**, the **Simulator Engine**, **Kubernetes**, **Ray**, and all internal AIOS services.

The API layer exposes business functionality while hiding infrastructure complexity. Every user action in the simulator ultimately becomes an API request processed by the backend and translated into autonomous infrastructure operations.

---

# 17.4 API Design Principles

The API shall:

* Follow RESTful principles.
* Use JSON for request and response bodies.
* Be fully versioned.
* Support pagination.
* Support filtering and sorting.
* Return standardized error responses.
* Provide OpenAPI documentation.
* Support role-based authorization.
* Remain stateless.

---

# 17.5 API Versioning

Every endpoint shall be versioned.

Example

```text
/api/v1/
```

Future versions

```text
/api/v2/

/api/v3/
```

Older versions remain backward compatible for a defined deprecation period.

# 17.6 Authentication

Authentication uses JWT.

Flow

```text
User Login

↓

Django Authentication

↓

JWT Generated

↓

Frontend Stores Token

↓

Token Sent With Requests

↓

Backend Verification

↓

Authorized Request
```

Headers

```http
Authorization: Bearer <JWT_TOKEN>
```

# 17.22 Standard Response Format

Successful response

```json
{
  "success": true,
  "data": {},
  "message": "Request completed successfully.",
  "timestamp": "2026-07-23T12:30:00Z"
}
```

Error response

```json
{
  "success": false,
  "error": {
    "code": "WORKLOAD_NOT_FOUND",
    "message": "Requested workload does not exist."
  },
  "timestamp": "2026-07-23T12:30:00Z"
}
```

# 17.23 Internal Service Communication

Not all communication uses REST.

| Communication              | Technology                    |
| -------------------------- | ----------------------------- |
| Next.js ↔ Django           | REST + WebSocket              |
| Django ↔ processors.py     | Internal Python service layer |
| processors.py ↔ Kubernetes | Kubernetes Python Client      |
| processors.py ↔ Ray        | Ray Python SDK                |
| processors.py ↔ Prometheus | Prometheus HTTP API           |
| processors.py ↔ PostgreSQL | Django ORM / Repository Layer |
| processors.py ↔ Redis      | Redis Client                  |
| Celery Workers ↔ Django    | Redis Message Broker          |

# 17.26 Functional Requirements

The API layer shall:

* Use **Django REST Framework** as the primary REST API framework.
* Serve a **Next.js 16.1.2** frontend through versioned REST APIs and WebSockets.
* Authenticate users using JWT.
* Expose endpoints for simulation, workloads, infrastructure monitoring, predictions, anomalies, dashboards, events, and administration.
* Deliver real-time updates through Django Channels and WebSockets.
* Communicate internally with Kubernetes, Ray, Prometheus, Redis, and PostgreSQL through dedicated service layers.
* Follow RESTful design principles with standardized request and response formats.
* Enforce authentication, authorization, validation, auditing, and secure communication for all endpoints.
* Maintain a clear separation between the presentation layer (Next.js), application layer (Django), and autonomous AI Control Plane (`processors.py`), ensuring that **all infrastructure decisions originate from processors.py rather than direct client requests**.
