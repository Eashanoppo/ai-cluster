# 14. ML Anomaly Detection

## 14.1 Purpose

The **ML Anomaly Detection Engine** is the **Intelligent Monitoring Layer** of the AI Cloud Operating System (AIOS).

Its purpose is to continuously analyze infrastructure telemetry, workload behavior, and operational metrics to detect abnormal conditions before they impact system performance or service availability.

Unlike rule-based monitoring, which only detects predefined thresholds, the ML Anomaly Detection Engine learns the normal behavior of the cluster and identifies deviations that may indicate hardware degradation, workload imbalance, resource leaks, inefficient scheduling, or impending failures.

The engine operates entirely **on-premises** using **local machine learning models** and **never relies on external AI APIs or cloud-based inference services**.

---

# 14.2 Objectives

The ML Anomaly Detection Engine shall:

* Continuously monitor the entire AI infrastructure.
* Learn normal operational patterns.
* Detect anomalies in real time.
* Predict abnormal system behavior.
* Identify hidden infrastructure issues.
* Assist processors.py in autonomous decision making.
* Reduce false alarms.

# 14.6 Machine Learning Models

The platform supports lightweight local ML models.

Initial models include:

### Isolation Forest

Detects rare infrastructure behavior.

Best for

* Resource anomalies
* Power spikes
* GPU utilization anomalies

---

### One-Class SVM

Learns normal cluster behavior.

Best for

* Unknown infrastructure failures
* Unusual workload execution

---

### Local Outlier Factor (LOF)

Detects abnormal local behavior.

Best for

* Worker anomalies
* GPU hotspots
* Queue abnormalities

---

### Autoencoder (Future)

Neural-network-based anomaly detection.

Best for

* Complex infrastructure patterns
* Multi-dimensional telemetry

---

### Time-Series Forecasting (Future)

Used to predict deviations before they occur.

Models may include:

* ARIMA
* Prophet
* LSTM (optional)

# 14.9 Anomaly Score

Every monitored entity receives an anomaly score.

Range

| Score       | Meaning         |
| ----------- | --------------- |
| 0.00 – 0.20 | Normal          |
| 0.21 – 0.40 | Minor Deviation |
| 0.41 – 0.60 | Warning         |
| 0.61 – 0.80 | High Risk       |
| 0.81 – 1.00 | Critical        |

Example

```yaml
GPU-07

Anomaly Score: 0.84

Confidence: 96%

Primary Cause:
Rapid temperature increase

Secondary Cause:
Power instability
```

# 14.15 Functional Requirements

The ML Anomaly Detection Engine shall:

* Analyze telemetry from NVIDIA DCGM, Prometheus, Kubernetes, Ray, Node Exporter, and AIOS services.
* Perform real-time anomaly detection using locally hosted ML models.
* Support Isolation Forest, One-Class SVM, and Local Outlier Factor as initial algorithms, with future extensibility to deep learning and time-series forecasting models.
* Generate anomaly scores, confidence scores, and probable root causes for monitored entities.
* Provide explainable anomaly reports to processors.py and Grafana.
* Continuously improve detection quality through local retraining on historical operational data.
* Detect infrastructure, workload, GPU, Kubernetes, Ray, and business-level anomalies.
* Operate entirely without external AI services or API tokens.
* Serve exclusively as an intelligence provider; all scheduling, migration, scaling, optimization, and recovery actions remain under the authority of the AI Control Plane (`processors.py`).
